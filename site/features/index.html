Mobile data and APN

Put a SIM card with a data plan in the device and Linux connects to 5G (NSA) or LTE by itself, then shares the connection with everything on the hotspot and the USB cable. If the modem resets, it reconnects by itself.

sudo mobile-data status        # is the connection up? which address?

The APN is the name of your operator's data gateway. Most operators need nothing: leave it empty and the device uses what the SIM card says.

SystemWhere to set the APN
Ubuntu/etc/mu300/mobile-data.conf: MU300_APN and MU300_PDP_TYPE
OpenWrtLuCI: Network > Interfaces > wan, or with uci (below)
uci set network.wan.apn='your.apn'; uci commit network; ifup wan

A fixed TTL

Every packet carries a small counter called TTL. Some operators look at it to tell hotspot traffic from the device's own. You can set a fixed value:

sudo mu300-ttl set 64          # a fixed TTL for mobile data
sudo mu300-ttl off             # back to the default

Also in mu300-toolkit (Network > TTL) and the control panel. On the mainline kernels the rule is in tc and flow offloading stays on; on 5.4 it is in nftables and offloading is off while a TTL is set. Check your operator's terms and your local law first.

Wi-Fi hotspot

The device broadcasts its own Wi-Fi network, on 5 GHz (802.11ac) or 2.4 GHz, one at a time. Unless you chose otherwise at install, it has the same name and password as under Android, so your phones join it as before.

SystemChange the name or password
Ubuntuedit /etc/mu300/hotspot.conf, then restart the service (below)
OpenWrtLuCI: Network > Wireless (the file is read only once, at the first start)
sudo nano /etc/mu300/hotspot.conf        # SSID=, PSK=, BAND=5 or 2.4, CHANNEL=auto, COUNTRY=
sudo systemctl restart mu300-hotspot

Wi-Fi client

Instead of being a hotspot, the Wi-Fi can join another network, like a hotel's or your home's. The device then uses that network for itself and shares it with its USB clients. It is one or the other: the Wi-Fi chip does one at a time.

sudo wifi-client scan                    # the networks in range
sudo wifi-client connect "NAME"          # asks for the password; nothing shows as you type
sudo wifi-client status
sudo wifi-client disconnect              # the hotspot comes back, and stays after a restart
  • Or with the menu: sudo mu300-toolkit > Network > Wi-Fi > "Join a network".
  • Give the password when asked, not on the command line: sudo writes the command line to the system journal.
  • Whether the radio is a client or a hotspot is decided at start-up. While it is the hotspot, connect saves the network and asks for a restart.
  • WPA2 and WPA2/WPA3 mixed networks work; WPA3-only networks do not (this Wi-Fi driver has no SAE). Set the router to mixed mode to join it.
  • USB clients reach only the internet through that network, not its other devices or its router, and the device's own services (SSH included) are closed to it. Reach the device over USB.
  • With both Wi-Fi and mobile data up, the Wi-Fi is used and the SIM stays idle.

USB network and serial console

Plugged into a computer, the device shows up as a network adapter, and the computer gets an address from it. The device itself is 192.168.77.1 on the F50 and 192.168.78.1 on the U30 Air, so one of each can be plugged into the same computer. Two of the same kind need /etc/mu300/lan.conf to tell them apart.

The USB network mode is NCM (with ECM as the fallback); the control panel can switch it to RNDIS, applied at the next start. The same cable also carries a serial console (ttyGS0), a login that works even when networking does not: screen /dev/cu.usbmodem* 115200 on a Mac. SSH and telnet are on.

SMS and USSD

Read, send and delete text messages on the SIM, and send USSD codes such as the one that shows your balance or your own number.

sudo sms list
sudo sms send NUMBER TEXT...
sudo sms delete INDEX
sudo mu300-ussd '*101#'                  # a USSD code, for example your balance

On OpenWrt with the control panel, SMS are under Cellular > SMS. That system syncs the SIM every 30 seconds, which marks unread messages on the SIM as read; the panel keeps its own unread state. Do not run sms delete read there.

VPN

A VPN sends traffic through a server of your choice, in an encrypted tunnel. Here it covers the device's own traffic and everything from its Wi-Fi and USB clients, with a kill switch: when the tunnel is down, nothing leaves the device.

It is an optional module, mu300-linux-vpn, installed on the device (or by the installer's question) and kept across updates. It keeps profiles of many kinds:

  • a WireGuard .conf (needs a mainline kernel), an OpenVPN .ovpn,
  • a VLESS, VMess, Trojan or Shadowsocks share link,
  • a Clash/mihomo YAML (add vpn-mihomo), or a raw Xray or sing-box JSON.
sudo mu300-extra install vpn                         # the module's latest release, checked against its SHA256SUMS
sudo mu300-vpn profile import ~/office.conf Office   # a WireGuard .conf, an .ovpn, a YAML or JSON file
sudo mu300-vpn profile import 'vless://...'          # or a share link
sudo mu300-vpn on
mu300-vpn status

Tailscale's traffic goes through the tunnel too. A device whose VPN is on with the kill switch fails closed when the module is missing: mobile data and the Wi-Fi client stay down until it is installed again or the VPN is turned off. Profiles, settings and the security model are in the module's README. Some carriers drop UDP and block OpenVPN.

The toolkit menu

mu300-toolkit is a menu like a Raspberry Pi's raspi-config: temperatures, CPU and RAM use, network speeds, performance profiles, stress tests, Wi-Fi, VPN, services and software updates, without remembering any command.

sudo mu300-toolkit                       # the menu
mu300-toolkit top                        # temperatures, CPU, RAM, network speed
sudo mu300-toolkit profile performance   # also eco, balanced
sudo mu300-toolkit stress all 10         # a stability test under load

Optional parts are called extras:

mu300-extra list
sudo mu300-extra install lang            # more web interface languages (OpenWrt)
sudo mu300-extra remove vpn

Battery, power and LEDs

The status LEDs mean what they mean under ZTE's firmware:

LEDF50 / MU300U30 Air
Networkblue: 4G, white: 5G, red: no serviceblue: 4G, white: 5G, red: no service
Wi-Fion while the hotspot is upwhite: 2.4 GHz, blue: 5 GHz
Battery-white: Linux is up
Heat alarmthe network LED flashes red, white, blue in turn: the chip is at 85 °Cthe battery LED flashes red, white, blue in turn: the chip at 85 °C or the battery at 50 °C
sudo mu300-led test            # find out which LED is which

On the U30 Air, mu300-power saves the battery: profiles (plugged, battery, saver, or auto), radios that go idle when nobody is connected, and a charge limit of 80 %. On OpenWrt with the control panel this is the System > Power page.

mu300-power status
sudo mu300-power profile battery         # plugged, battery, saver or auto
sudo mu300-power set battery.WIFI_IDLE 10

A start that began because a charger was plugged in stays a charging start (LED blinking, hotspot and modem down) until you press the Wi-Fi key.

U30 Air extras

What it does
Batterylevel, voltage, current, temperature and charging state in mu300-toolkit, the control panel and /sys/class/power_supply, on every kernel. Charging: on 5.4 by the vendor charger stack, on 6.18 and 7.2 by the bq256xx driver from v2026.10.12 on
Buttonspower: a short press wakes the LEDs (they go dark after 60 s), held 3 s shuts down. Wi-Fi key: switches the hotspot between 2.4 and 5 GHz, held 3 s turns it off or on
NFCa phone held to the device joins the hotspot, as under ZTE's firmware
USB hostwith an OTG adapter on the mainline kernels: flash drives (FAT, exFAT), keyboards and mice, USB modems and Ethernet adapters
sudo mu300-nfc                 # shows the tag
sudo mu300-nfc wifi            # writes the hotspot's name and password
sudo mu300-usb host            # U30 Air, mainline kernels: an OTG adapter, 5 V from the battery
sudo mu300-usb device          # back to the computer (the default at every start)

On the F50 the USB port is its power supply, so it has no USB host mode; holding its power button 3 s shuts it down.

Bluetooth, GPU, KVM, languages

  • Bluetooth: BlueZ; scanning works.
  • GPU: the Mali-G57 runs OpenCL 3.0, with no screen.
  • KVM: /dev/kvm on all three kernels, for virtual machines.
  • Memory: about 1.4 GB usable, plus compressed swap in RAM (zram).
  • Web interface languages (OpenWrt): English, Turkish and Simplified Chinese out of the box; 40 more for LuCI and 29 more for the control panel with the lang extra. Switch under System > System > Language and Style, or System > Languages on the control panel. The panel's other translations are machine translations, and corrections are welcome.

What does not work

  • Screen outputHDMI over USB-C: the USB-C power chip never answers.
  • SoundNo speaker or microphone on the board; call audio through the modem is work in progress and not in the releases.
  • WPA3-only Wi-FiThe Wi-Fi driver has no SAE; mixed WPA2/WPA3 works.
  • Hotspot and client at onceThe Wi-Fi does one at a time.
  • Monitor modeThe Wi-Fi chip offers station and access-point mode only.
  • GPSThe device has none, so websites guess your location from the IP address.

The complete table is in the README under what works and what does not.
